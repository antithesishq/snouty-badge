# Snouty - Run Study 05

A new 16-frame, two-step running animation derived from the supplied Snouty
artwork. This is the run-only review pass. Sliding, idle, jumping and landing
are intentionally not included pending approval of the run.


## Revision note

This pass keeps the approved Study 04 body, tail, and gait revisions intact, and updates only the chest logo so the pixel-art emblem better matches the supplied Antithesis mark.

## Review first

- `snouty_run_preview.gif`: 4x nearest-neighbor preview, scrolling ground.
- `snouty_run_isolated.gif`: enlarged loop on a plain background.
- `snouty_run_slow.gif`: same order at 100 ms/frame for pose inspection.
- `snouty_run_contact_sheet.png`: all 16 poses, numbered and labeled.

The backgrounds in the review GIFs are not baked into the sprite assets.

## Animation settings

Native cell: 96 x 96 pixels. Direction: right.
16 distinct frames, 40 ms each: 25 fps and 640 ms per complete cycle.
Play 00, 01, ... 15, then return to 00. Do not play ping-pong, do not reorder,
and do not append a second copy of frame 00 at the end.

Fixed origin: (48, 88), using top-left image coordinates.
Ground baseline: y = 88. All cells retain the same padding and origin.
No automatic frame-by-frame trimming or recentering should be applied.
Place the cell at (character_x - 48, ground_y - 88).

The near foot contacts at frame 00; the far foot contacts at frame 08.
Frames 06-07 and 14-15 are the flight intervals.
While planted, the toe travels left 6 native pixels per animation frame.
This corresponds to a nominal rightward world speed of 150 native pixels/sec.
The preview ground scrolls at this same rate and wraps exactly at the loop.

For a different playback speed, scale world speed proportionally. In a game,
timing and movement can be decoupled, but the planted feet will slide if their
rates are no longer matched. At 50 ms/frame, for example, use 120 px/sec.

## Sprite assets

- `frames/snouty_run_00.png` through `snouty_run_15.png`: transparent RGBA cells.
- `snouty_run_strip.png`: horizontal RGBA strip, 1536 x 96, no gutters.
- `snouty_run_sheet.png`: RGBA grid, 8 columns x 2 rows, 768 x 192, row-major.
- `snouty_run_indexed.png`: same horizontal strip, 4-bit indexed PNG.
- `snouty_run.png`: native-resolution transparent animated PNG (APNG).
- `snouty_run_native_transparent.gif`: native transparent GIF.
- `snouty_run.json`: frame rectangles, timing, palette, origin and gait metadata.
- `snouty_palette.gpl`: 15-color opaque palette for compatible pixel editors.

The sprite art uses 15 opaque colors plus transparency. Alpha is strictly
0 or 255, and the indexed PNG uses palette index 0 for transparency.
All preview enlargement is nearest-neighbor. Use nearest-neighbor sampling
and integer scale factors when displaying the art.

This is a retro-styled asset, not a platform-specific tile/VRAM export or a
claim of conformance with an original console's complete hardware limits.

## What changed in Study 05

Compared with the prior pass, the only intended visual change is the chest emblem. The run cycle, silhouette, timing, palette, tail placement, and compact rear hem remain the same.

## What changed from the supplied strip

The head, hands, tail and net use the supplied character artwork, reduced to
a fixed native pixel grid and fixed palette with targeted pixel cleanup.
The torso was rebuilt with a small number of hard-edged shade regions; the
chest emblem and net handle were cleaned up. The legs are newly drawn and
animated, not crops or reordered frames from the original eight-frame strip.

Near and far legs retain their identities throughout the complete cycle.
Foot planting, heel lift, folded recovery, forward reach and airborne phases
are explicit. The two recovery paths are different, rather than one copied
half-cycle with the limbs swapped. Slightly different step compression,
head settling, free-arm counter-swing, tail follow-through and delayed net
movement add secondary motion without changing the character's pixel grid.

## Rebuild and validation

Requires Python 3.10+, Pillow and NumPy. Keep the included assets/ directory
next to the scripts; the uploaded ZIP is not needed to rebuild the package.

    python build_run.py
    python validate_run.py

The source art layers are in assets/. Frame definitions, phase paths, timing,
palette and body offsets are in build_run.py. The torso is generated by the
script and its asset-layer PNG is overwritten when rebuilding.

Validation checks pixel colors, binary alpha, cell bounds, distinct frames,
atlas cells, the indexed export, APNG/GIF frame counts and timing, exact native
GIF-to-PNG pixel equality, and planted-toe travel. validation.json contains
the results and adjacent-frame pixel differences including frame 15 -> 00.
These structural tests do not substitute for judging the animation's feel.

Artwork provenance: derived from the Snouty reference provided in this chat.
